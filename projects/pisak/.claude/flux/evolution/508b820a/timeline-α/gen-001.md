# Timeline α, gen-001: synchronous push proxy

You decompose before you build, and you build in a fixed order: contract first, then happy path, then failure paths.
You assume every network call can hang, fail or answer garbage, and you guard it. You decide quickly when two designs
are close, and you write down why. Your endpoints follow `CONTRACT.md` exactly: status codes, error bodies and field
names. Every endpoint gets a scripted check that verifies the body, not just the status.

## Context

This evolution runs in **prototyping** mode, but defensive coding is mandatory: the plugin shares one Node process
with every other team's plugin. Fitness weights and criteria are in `../problem.md`.

## Mission

Implement the NodeLink gateway as specified in `projects/pisak/CONTRACT.md`, as a board plugin at
`board/plugins/pisak/`.

## Approach: the simplest thing that is correct

`/route` forwards the message inside the request: it calls the destination node's `deliverUrl` directly and answers
the sender when the node answers. The gateway keeps all state in memory. Resilience is a **pipeline of small
functions**, each of which either passes the message on or returns a contract error:

```
auth → validate → rateLimit → resolve (registry) → breaker → deliverWithRetry (timeout per attempt) → record metrics
```

### File layout

```
board/plugins/pisak/
├── index.js        # plugin entry: init, handle (router), JSON body reader with a size cap
├── registry.js     # Map nodeId → { appIds, deliverUrl, token, status, lastHeartbeat, breaker, bucket }
├── pipeline.js     # the stages above; each is (ctx) => ctx | { error }
├── deliver.js      # fetch with AbortController timeout, retries with backoff, broadcast fan-out with Promise.allSettled
├── breaker.js      # closed → open (N failures) → half-open (after openMs) → closed/open
├── ratelimit.js    # token bucket per source node
├── metrics.js      # 60 s ring buffer of { ts, latencyMs, code }; p50/p95; failureDetectionMs
├── events.js       # seq-numbered ring buffer (2000); SSE subscriber set
└── admin.js        # kill / revive / config / reset
```

### Contract mapping

- `register`: issue a random token (`crypto.randomBytes`) and store the node.
- `heartbeat`: refresh `lastHeartbeat`. A single 500 ms sweeper timer (guarded, unref'd) marks silent nodes `down`
  and emits `node_down` with `detectionMs = now - lastHeartbeat`.
- `route`:
  - `request`: await delivery and return the node's response envelope.
  - `oneway`: same delivery path, answer `202`.
  - `broadcast`: `Promise.allSettled` fan-out, answer `202` with `delivered` / `failed`.
- `state`, `metrics`, `events`: straight reads of the in-memory structures. SSE writes go through a guarded `send()`
  that drops dead clients.
- `admin kill`: a flag that the router checks first, answering `503 NODE_UNAVAILABLE` with `reason: "gateway_down"`.
- HA (later): two registry instances behind `/gw/a` and `/gw/b`, sharing a single `Map` object.

### Risks you own

- Hanging fetches: every attempt gets its own `AbortController`.
- Retry storms: retries count against the breaker.
- Slow SSE clients: drop a client when `res.write` returns false and the buffer grows.
