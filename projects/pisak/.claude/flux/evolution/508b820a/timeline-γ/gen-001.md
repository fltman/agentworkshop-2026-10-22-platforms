## Mission

Implement the NodeLink gateway as specified in `projects/pisak/CONTRACT.md`, as a board plugin at
`board/plugins/pisak/`.

## Approach: one append-only log, everything else is a projection

Every fact is an event appended to an in-memory log: a node registered, a message was routed, delivered or failed, a
breaker changed state, a heartbeat was missed, the gateway was killed. The rest of the gateway is a set of
**projections** that fold over that log:

- `registry` (nodes, apps, tokens, status) ← `node_registered` / `node_deregistered` / `node_down` / `node_up`
- `breakers` ← `delivery_failed` / `delivery_ok` / `circuit_*`
- `metrics` (60 s window, p50/p95, error rate, failureDetectionMs) ← `message` events
- `GET /events` and `/events/stream` *are* the log: no separate event plumbing
- **HA:** instances a and b each own their projections, and both apply every event from a shared log. Killing a means
  only that a stops answering; b already has the full registry. So the stretch goal is nearly free.

Routing still uses push delivery to `deliverUrl`, with timeout and retries: the log records it, it does not replace it.

### File layout

```
board/plugins/pisak/
├── index.js        # plugin entry, router, JSON body reader with a size cap
├── log.js          # append(event) → seq; bounded ring (keep 2000 plus snapshots for projections); subscribe(fn)
├── projections.js  # registry, breakers, buckets, metrics: pure reducers (state, event) → state
├── commands.js     # register/route/heartbeat/admin: validate → decide using projections → append events
├── deliver.js      # fetch with timeout and retries; appends delivery_ok / delivery_failed
├── instance.js     # Gateway instance {id, alive}; a and b share log.js, each mounts the same API under /gw/<id>/api
└── sse.js          # tails the log to SSE clients
```

### Contract mapping

- Every contract endpoint is a **command** that reads projections and appends events. Reducers are pure and
  synchronous, so they are trivial to unit test. That is where `testing: 0.5` goes.
- Log compaction: the projections keep their own current state, so the ring buffer can drop old events safely.

### Risks you own

- Over-engineering: if the projections are not working end to end by gen-002, simplify. A Map plus a log is acceptable.
- Reducer exceptions: one bad event must not poison the projection. Wrap `apply()` and log with the `[pisak]` prefix.
- Replay cost: never replay the full log on the hot path; projections are incremental.
